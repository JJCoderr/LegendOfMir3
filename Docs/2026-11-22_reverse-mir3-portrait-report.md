# Mir3.exe 头像设置核对

原版的头像上传与重置都使用游戏消息 `1151`，消息头其余字段为零。上传的正文是按字节编码的 JPEG，重置的正文为空。原版上传后在客户端写入 FAC，重置后删除 FAC。两条路径均在发送函数返回后继续处理本地状态。

## 样本与证据

| 证据 | 观察 |
| --- | --- |
| E-001 | 本机原件 `G:/传奇3/宝藏传奇3/Mir3.exe` 的 SHA-256 为 `FDCE0CF98757D64C18EB08F9346842E7028B93070872CD4C50A0BD116FD47195`，与 Godot 分支的 HUD 核对记录一致。 |
| E-002 | IDA 会话 `mir3-cui-portrait` 使用同一原件的既有解包分析副本，SHA-256 为 `08F68B794BFB28803D1132C02B26D2595DBA309BE5B2B475AE0CDFE6A752F8AA`。架构为 x86，基址 `0x400000`，入口 `0x4A14EC`。IDA 的标准导入模块数为零，分析以指令和调用链为依据。 |
| E-003 | 面板确认处理 `0x41ECC0` 校验 JPEG，限制文件为 4095 字节，上传间隔为 1000 毫秒。在 `0x41EE97` 调用发送函数后，经 `0x47D4C0` 封装并写入 `Data/<区服>_<角色>.fac`。重置在 `0x41EFDA` 调用相同发送函数，参数均为零，随后删除该缓存。 |
| E-004 | `0x47D360` 构造 `1151` 零参数消息，`0x47C730` 使用明确的二进制正文长度编码、有序帧号及游戏消息边界。 |

核对时用 IDA 的 `survey_binary`、`decompile` 和 `xrefs_to` 分析上述地址。原始结果与反汇编保存在 `build-cui/portrait-ida`。原件只用于计算哈希。

## 客户端移植

E-003 与 E-004 对应 `Client/Dialogs.cpp` 的确认及重置交互，以及 `Client/CuiClientState.h` 的消息封装。上传缓存使用同目录临时文件原子替换。窗口继续使用 Godot 分支的布局、提示、选中和滚动逻辑。

## 其他玩家头像

| 证据 | 观察 |
| --- | --- |
| E-005 | `0x47D3A0` 构造 `1152` 零参数消息，正文传入目标角色名。`0x43F060` 使用玩家照片选项、资源目录缓存及照片版本决定是否发起查询。 |
| E-006 | `0x411700` 从 16 字节人物信息的偏移 8 读取 DWORD 照片版本。版本变化时置刷新标记。 |
| E-007 | `0x42CBE8` 的二级跳转表将 `1403` 分派到 `0x42D2EF`。该分支合并消息头的前两个数据 WORD，按识别号定位人物，由 `0x42D664` 解码最长 4096 字节的 JPEG。版本为零时走无照片分支。 |

CUI 用人物精灵的矩形识别悬停目标，以角色标识和版本匹配回复，按当前地图缓存有效照片。局内“玩家照片”开关同时控制查询和照片显示。职业头像使用 ProgUse，紧凑聊天的自定义照片区域沿用 Godot 坐标。原版还使用 `UserPic.ini` 索引其他玩家照片的磁盘缓存，CUI 当前使用局内内存缓存。测试网关用于核对协议，真实服务端待联调。
