# Mir3 怪物目标面板协议核对

范围为用户提供的宝藏版 `Mir3.exe`、Godot 客户端源码和本地测试网关。以 IDA 9.1 读取同一原客户端的现有解包分析副本，核对怪物目标属性的请求、回复和绘制。核对结果用于 [CUI 场景状态](../Client/CuiClientState.h) 和 [目标面板](../Client/Dialogs.cpp)。

## 证据和结论

分析库记录的样本为 PE x86，映像基址 `0x400000`，SHA-256 为 `08f68b794bfb28803d1132c02b26d2595dba309be5b2b475ae0cdfe6a752f8aa`。已保存本地 `build-cui/target-ida` 中的反汇编和反编译摘录。

| 证据 | IDA 复查位置 | 结论 |
| --- | --- | --- |
| E-001 | `survey_binary`，`detail_level=standard` | 解包分析副本的导入分类为空。本次通过函数调用和字段写入核对协议。 |
| E-002 | 反汇编 `0x4248F7`、`0x47BEC0`、`0x47D8B0` | F-001。目标属性图标为 `-1` 时，查询路径以目标标识填入 `Recog`，以目标格位 X、Y 分别填入 `Param`、`Tag`，`Series` 为零，正文为空。消息号为 `1047`。 |
| E-003 | 检查 `0x4282C0` 的 `1304` 分支 `0x42C9A3` 及 `0x438310` | F-002。回复按目标标识查找演员，正文解码为 10 字节。第一个、第二个参数分别写到属性类别和状态，状态为 1 时使用徽记 635，其余使用 634。 |
| E-004 | 反编译 `0x4081F0`，在 `0x4AF464` 查看浮点常量，查看 Godot `TargetPortraitVitals` | F-003。`53` 的当前血量和最大血量对应第一个、第三个参数，百分比按两者比率乘 100 后截断。容量为零时百分比为零。血条使用比例裁剪。 |

F-001 至 F-003 均由对应的反汇编或反编译验证，结论用于客户端互操作。

## 调用路径

P-001 为目标切换至面板更新的调用路径。先由 `0x4248F7` 检查缺失属性并经 `0x47BEC0` 发出查询（E-002，F-001），再由 `0x42C9A3` 按回复标识写入缓存，`0x438310` 按状态选徽记（E-003，F-002）。血量独立由 `0x4081F0` 更新（E-004，F-003）。

本地网关使用 X、Y 不同的怪物坐标验收 `1047` 字段顺序，并检查截断的 `1304`、迟到回复和已移除目标。Godot 实际视口使用相同属性和血量绘制参考画面，CUI 使用鼠标命中真实怪物精灵打开目标面板。
