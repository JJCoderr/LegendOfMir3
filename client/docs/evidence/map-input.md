# 换图后的普通左键延迟

## 原版证据

2026-11-14 使用现有 IDA 分析库实时核验，镜像 SHA256 同 map-wire.md。

- `0x42EE30`：换图函数向 `this+0x437BD8` 写入 1500，`this+0x437BDC` 清零。
- `0x4242C6..0x4242E6`：累计帧时间；累计值大于或等于时限时，两字段清零。该代码先于同帧公共地图队列消费，因此不能在刚建立延迟的帧再扣一次旧帧时间。
- `0x4277D0`：`WM_LBUTTONDOWN=0x201` 分发到 `0x4264D0`；右键、左键释放及键盘分属其他函数。
- `0x42655A`：普通左键按下处理读取 duration，非零则返回；早于地图拾取、NPC、移动和普通界面处理，晚于模态窗口处理。

扫描到其他写入场景有 300、500、1000ms；本批仅实现换图的 1500ms，不推断这些场景的触发条件。两套早期 C++ 使用 2300ms，优先采用目标原版的 1500ms。Zircon NextActionTime 与 mir2x 的角色事件门禁不能替代本字段，见 ../../RERENCES.md。

## 实现范围

`MapInputDelay` 保存剩余时间；成功 `change_map` 重置为 1500ms，失败不改变。每帧先推进延迟，再消费排队地图消息。此状态不控制地图绘制，也不阻止服务器更新人物或对话。

视图处理普通左键按下前检查延迟；模态确认先处理。鼠标释放仍走原有清理路径，键盘、右键和鼠标移动不套该检查。被阻止的按下不登记为持续左键，因此延迟结束不会自动补发拾取或 NPC 请求。直接 `walk_to_map_cell` 属于程序接口，不等价于鼠标输入，不加这个门禁。

本改动没有增加贴图、字体或资源索引，仍使用配置目录中的原资源。人物淡入、键盘触发的其他延迟写入、模态例外完整原版对照仍未全部完成。

## 验证

- CMake Release 构建。
- `hud_checks.exe --map-input`：默认无锁、1499ms 仍锁、1500ms 恰好解除、连续换图重计时、负时间不改状态、长帧钳制。
- Godot `--map-input --screenshots`：延迟期间本格左键不拾取、NPC 点击不发请求、键盘可打开选项；失败切图不重计时；期满拾取与 NPC 恢复，不补发旧点击；右键在延迟期间可移动。
- `--map-wire --screenshots` 定向回归地图消息、中文名称和对话保留。
- 真实截图：client/build/screenshots/map-input-keyboard.png、map-input-restored.png。

上述验证仅覆盖换图左键延迟，不能据此宣称全套输入、淡入或整张主界面已与原版逐像素一致。
