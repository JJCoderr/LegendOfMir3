# 换图后的普通左键延迟

## 原版证据

2026-11-14 使用现有 IDA 分析库实时核验，镜像 SHA256 同 map-wire.md。

- `0x42EE30`：换图函数向 `this+0x437BD8` 写入 1500，`this+0x437BDC` 清零。
- `0x4242C6..0x4242E6`：累计帧时间；累计值大于或等于时限时，两字段清零。该代码先于同帧公共地图队列消费，因此不能在刚建立延迟的帧再扣一次旧帧时间。
- `0x4277D0`：`WM_LBUTTONDOWN=0x201` 分发到 `0x4264D0`；右键、左键释放及键盘分属其他函数。
- `0x42655A`：普通左键按下处理读取 duration，非零则返回；早于地图拾取、NPC、移动和普通界面处理，晚于模态窗口处理。

扫描到其他写入场景有 300、500、1000ms；本批仅实现换图的 1500ms，不推断这些场景的触发条件。两套早期 C++ 使用 2300ms，优先采用目标原版的 1500ms。Zircon NextActionTime 与 mir2x 的角色事件门禁不能替代本字段，见 ../../RERENCES.md。

## 实现范围

`MapInputDelay` 保存剩余时间；成功 `change_map` 重置为 1500ms，失败不改变。每帧先推进延迟，再消费排队地图消息。此状态不控制地图绘制，也不阻止服务器更新人物或对话。

视图处理普通左键按下前检查延迟；模态确认先处理。鼠标释放仍走原有清理路径，键盘、右键和鼠标移动不套该检查。被阻止的按下不登记为持续左键，因此延迟结束不会自动补发拾取或 NPC 请求。直接 `walk_to_map_cell` 属于程序接口，不等价于鼠标输入，不加这个门禁。

本改动没有增加贴图、字体或资源索引，仍使用配置目录中的原资源。人物淡入、键盘触发的其他延迟写入、模态例外完整原版对照仍未全部完成。

## 验证

- CMake Release 构建。
- `hud_checks.exe --map-input`：默认无锁、1499ms 仍锁、1500ms 恰好解除、连续换图重计时、负时间不改状态、长帧钳制。
- Godot `--map-input --screenshots`：延迟期间本格左键不拾取、NPC 点击不发请求、键盘可打开选项；失败切图不重计时；期满拾取与 NPC 恢复，不补发旧点击；右键在延迟期间可移动。
- `--map-wire --screenshots` 定向回归地图消息、中文名称和对话保留。
- 真实截图：client/build/screenshots/map-input-keyboard.png、map-input-restored.png。

上述验证仅覆盖换图左键延迟，不能据此宣称全套输入、淡入或整张主界面已与原版逐像素一致。

## 骑乘批次补证修正
原先“右键可移动”的结论只核对了窗口消息分发，遗漏角色移动入口417E10/418660；现已确认两者检查同一个延迟字段，技能入口4197C0/4199A0也检查。已接通共用动作限制并纠正对应测试；原文保留为历史范围，当前依据以mount-wire.md为准。

### 普通近战输入

定向验收 `melee_input.gd -- --player-gate --screenshots` 使用独立选项文件关闭AttackUser。验证白名普通点击没有动作请求、Shift发送CM_HIT、颜色索引125与69允许普通攻击，以及恢复255后再次禁止普通攻击。该入口直接建立相邻玩家，输出MELEE_PLAYER_GATE_OK和melee-player-gate.png。

### 动作时间戳复核

417C40在415F90动作11入口先执行，失败直接返回。415510初始化乘数为7×20×10=1400、5×30×10=1500，并初始化等级减免上限370、总减免上限800。+403572是能力记录首字节等级，+403605/+403606分别对应手持重量和上限。+403452通过411BA0读取消息参数WORD，计算时按有符号16位解释。

```text
减免 = min(800, min(370, 14 × 等级) + 60 × 有符号速度)
间隔 = 1400 − 减免
若手持重量 > 手持上限：间隔 += 1500
若DWORD(当前时间 − 上次获准攻击时间) <= DWORD(间隔)：拒绝
否则记录当前时间，继续415F90动作11
```

417C40使用+403668（0x628D4）记录获准时间，比较为严格大于。419B40则用+403724检查相同动态间隔的0.8倍，并检查移动后480毫秒。二者是连续两层条件，当前Godot普攻入口尚未接入这些时序。已核对0x400000–0x49F000代码区的直接偏移引用，+403720仍只见初始化写入；间接写入尚未排除。

419B40检查的480毫秒字段为+403716（0x62904）。415F90的动作21/30与22/31，在准备发送3011或3013时写入当前计时值。因此该门限是移动发起后的共用动作限制。普通攻击另写+403724，动态攻击间隔由419B40前半段的属性字段参与计算，不能将480毫秒直接作为固定普攻间隔。

800毫秒检查对应+403720（0x62908）。当前在0x410000–0x420000范围内仅确认415510初始化清零，尚须查明其他写入来源。418D80中技能34/35使用的0x628F8/0x628F4是另外两处时间戳，门限为严格大于10000毫秒。

```text
发起移动 → 419B40检查共用动作门限 → 写入+403716 → 发送3011或3013
发起普攻 → 419B40检查动态属性间隔及共用门限 → 写入+403724 → 发送3014
下一步恢复属性字段与全部写入来源，再接入非阻塞的客户端动作等待
```

4264D0 的目标门禁允许 Shift、类型3、名称颜色255或27631、AttackUser任一条件通过。+4424908 由426EF0的220键分支翻转，提示1515/1516与选项窗口中的AttackUser一致。类型3部分特殊形状返回无目标路径，包括低字节26、86、113–115、165、166，以及形状530–533且朝向7。

417E10 以命中对象的格坐标定向。普通武器以向零截断的欧氏距离判断近战：距离为1时，骑乘不出招，可攻击的目标进入415F90动作11；可追随的目标尝试沿目标方向移动。距离更远时，若目标方向的相邻格可通行则先走一步。武器外观34–37走独立的远程分支。

415F90 的普通攻击分支调用4702F0选择挥击动作，再由47BC30发送3014。包体识别字由动作格X与Y分别装入低、高半字，三个参数依次为系统毫秒计数低半字、朝向、计数高半字。普通挥击的动作号按武器外观分为9、10、13，其中2、3、6、16、17、19用13，4、5、7、15用10，其余用9。419B40另检查与最近两类动作时间戳的差值，门限分别为480和800毫秒。两处时间戳的写入来源仍须核对后再接入。

### 普攻频率门禁实现与定向验收（2026-11-14）

本批落实417C40准入判定，复用上文伪代码。40D8C0对801、807、808调用虚表+116；4AF510/4AF5FC指向411BA0，该函数把消息+10的WORD写入+403452。Godot将本地角色对应参数3解释为int16_t并参与间隔公式；等级和手持负重来自已有能力模型。保留原有807灯光处理，本批不宣称完整实现该状态消息的其他效果。

普通近战和矿镐动作11在播放动画、转向及发包前执行准入检查。拒绝不会刷新最近获准时间，接受时记录系统DWORD计时；退出场景或切换角色清零，普通地图切换保留。属性在每次尝试时读取，变化立即影响间隔。

Release构建通过。hud_checks --melee-cooldown覆盖等级上限、速度上限、负速度、等重/超重、严格边界、拒绝不续期及计时回绕。melee_cooldown.gd直接建立相邻怪物，验证动画结束后仍不提前发包、间隔期满恢复、负速度与超重、速度更新、矿镐共用限频；输出MELEE_COOLDOWN_UI_OK。两项在一次集中验收中通过，约6秒。实际截图client/build/screenshots/melee-cooldown-attack.png。没有执行全游戏组合场景。

实现范围仅为417C40频率门禁。419B40中的0.8倍间隔及移动后480毫秒等待、另一个800毫秒字段的写入来源仍待闭环，不能把本批视为全套动作时序完成。
