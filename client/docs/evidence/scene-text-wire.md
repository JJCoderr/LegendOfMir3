# 场景名称、聊天与移除原始消息

功能对照和选择理由见 ../../../reference/HELP.md。名称和聊天颜色以旧项目 1.45 IDA 分析为准，离场/清场默认队列参考两套 C++ 客户端实现；不是完整原版时序验收。

apply_scene_message 现在分发 42 名称、656 改色、40/1501 公开/NPC 气泡与聊天日志、100..104 其他日志。载荷六位解码后按 ANSI 转换，遇 NUL 截止；气泡输入上限 259 字节，聊天日志仍保留原有 200 ANSI 字节限制。名称沿用三行解析，颜色取第一参数低字节。聊天前景/背景取第一/第二参数低字节，使用独立 1.45 调色板，104 固定绿字黑底。合法但发送对象不在场时仍记录聊天，不创建虚假对象或气泡。

30/633 必须无消息体，进入独立默认移除队列，在场景更新入口统一处理。30 只清指定远端对象，重复移除无副作用；633 清所有远端人物/NPC/鸡，保留本地玩家和聊天历史。移除复用既有清理函数，删除动作队列、名称、气泡、血条/数字、音频及目标关联；所属 NPC 对话关闭。相同 ID 重建不继承旧对象状态。

验证：Release CMake，hud_checks --scene-text 检查 1.45 调色板与消息分类；Godot --scene-text 注入 GBK 中文三行名称/发言、改色、缺席对象行会消息、NPC 发言、畸形载荷、重复离场、ID 重用、清场后本地气泡/聊天保留及 NPC 对话关闭。截图 bichon-wire-name-speech.png 与 bichon-wire-clear-scene.png 来自实际视口。测试无需全场景回归。

仍未启动真实服务器，也未接入本地角色真实网络 ID 映射；0 仅是本地显示适配 ID。默认消息处理的精确原版阶段、其他对象类别的生命周期仍需补齐。
## 动物同帧重新入场

4282C0 将 30 和 633 投入无正文默认队列。Godot 保留逐帧消费路径。当随后收到可建立动物的有效入场包时，如存在针对该编号的移除或前置清场，先处理这些默认消息，再以新包创建对象。离线重放覆盖 30 和 633 后同帧复用鹿编号，并检查尸体状态清除、新光源保留以及最终离场。Release、map_butch.gd 和 hud_smoke.gd --scene-text 通过。原版默认队列的精确调度仍待实机对照。
## 怪物入场名称

4085A0 先解码22个编码字符得到16字节外观，余下内容单独解码。408450 拆分最多三行名称，并从斜杠后的字节取得颜色。Godot 在 20 号入场包中读取后缀，复用场景名称绘制。离线以 GBK「猪」及颜色249验证悬停，Windows Release、map_butch.gd 与 --scene-text 通过。截图 map-pig-name.png。
## 怪物外观变更

4282C0 将41号怪物消息交给虚表 +40，407B70 解码16字节外观并用4064B0刷新形状，同时应用血条状态位。Godot 验证新形状的当前动作资源后替换显示，沿用对象编号、坐标和朝向。Windows Release 和 map_butch.gd 通过，回放覆盖猪与半兽人跨库切换后恢复猪的移动、死亡和割肉。
409600 在处理怪物受击时调用 4064B0 应用类型3外观，再根据生命和伤害选择死亡或受击。Godot 先验证新形状所需帧，再应用形状、生命和动作。离线回放用 1309 将半兽人外观切回猪并继续行走和割肉。血条状态位仍由独立状态、入场与移动消息驱动。
4082F0 和 409500 在开始怪物行走前调用 4064B0，使用该条消息携带的外观。Godot 将形状随动作排队，到开始时校验目标朝向的资源并同步更新。Release 与 map_butch.gd 通过，回放覆盖猪行走、半兽人后退和同格转向恢复猪外观。
4093B0 在处理怪物32、33和34时先读取位置及朝向，再刷新外观并选择对应尸体动作。Godot 校验目标外观资源后替换形状。32 固定在死亡末帧，33 进入骨架，34 对首次死亡播放动画。Windows Release 和 map_butch.gd 通过，回放覆盖半兽人外观收到猪的32号消息，随后按猪尸体发出割肉请求。
