# 背包物品使用网络闭环

## 原版证据

实时IDA核对4418D0、47C0E0汇编、4282C0的635/636、43EED0及41AC50。没有复用旧Godot业务代码。

4418D0禁止重复待确认使用、装备来源和资源1050所指金币。普通背包释放快速点击经过既有冷却判断，必要时先交换鼠标下物品，再标记待确认并请求1006。47C0E0读取计时值，构造recognition=MakeIndex、参数一=计时低WORD、参数二=0、参数三=计时高WORD，正文ANSI名称。当前客户端使用既有单调毫秒计时的低DWORD，并与其它请求共享序号。

635普通背包分支显示资源1464使用提示；物品名等于资源1409栗子加0至9时，提示去掉数字后缀。43EED0按StdMode播放音效：0用108，1或2用107，其它不播放。堆叠模式3且原数量大于1时，以参数一WORD更新持有记录和背包中同编号记录，然后放回原位置；不做本地减一。原数量小于等于1时删除首个编号和名称同时匹配的背包副本并清除持有记录。其它模式直接清除持有物品。

636普通背包分支恢复原物品和数量；模式51额外用资源1414打开103类单按钮提示。金币和快捷物品来源转入41AC50快捷物品栏恢复；普通背包金币请求已在入口禁止，因此不伪造这一来源。现有提示框确认关闭路径复用，不能用Escape假定关闭。

## 实现

- 使用信号保留，同时真正发送CM_EAT原包，接入SM_EAT_OK/SM_EAT_FAIL。待确认期间禁止重复请求；无待确认对象时拒绝过时回包。
- 复用背包模型的服务器数量/末件规则，并将更新数量同步到保存的100字节原始记录WORD71，避免模型数量与原记录分离。
- 成功文案、栗子名、金币禁用名和特殊失败文案均从外部CmList.dat读取；未硬编码产品文案。
- 模式51失败走现有警告框，恢复物品后打开，不发额外网络请求。
