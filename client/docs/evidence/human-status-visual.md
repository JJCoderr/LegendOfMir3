# 人物状态颜色与外观状态同步

2026-11-14实时IDA复核405C40、405CB0、414870、411C00、411D40、4120A0、412000，并复用已确认的411700/412500和入场外观结构。目标镜像身份同map-wire.md。

405C40从角色+400396读取状态，各位按后写覆盖先写。最终优先级从高到低：0x00020000 -> 模式1；0x80000000 -> RGB565 2016；0x40000000 -> 64690；0x08000000 -> 38079；0x20000000 -> 64511；0x04000000 -> 灰度模式0；0x00800000 -> 模式1；无匹配 -> 65535普通绘制。

414870将同一状态模式传给坐骑、前后武器、身体与头发的405CB0绘制。模式1走48EF15的8/32源权重混合；其他已知颜色模式走490821的RGB565状态处理，覆盖普通染色。复用怪物已核对的颜色公式和屏幕背景混合，人物不再只保存状态而缺少绘制。马匹帧同时保留原WIL区域标记，使颜色处理覆盖坐骑实际像素。

411C00/411D40/4120A0及死亡链412000->411700读取完整外观状态DWORD，并同步bit1血条校验。入场外观同样建立本地状态。412500受击只通过基础外观更新，不覆盖+400396；因此本地与远端受击都保留旧状态，不把受击载荷中的其他字段误作状态重置。远端普通外观消息在出队成功后同步状态及血条校验。

```text
完整状态外观出队 -> 保存状态 -> 更新血条校验 -> 绘制使用新模式
受击外观出队 -> 更新基础外观，保留状态
绘制身体/头发/前后武器/坐骑
  模式1：按8/32与已绘场景混合
  状态色/灰度：原RGB565变换
  普通：原衣服与头发染色
```

验收：Release构建通过；human_status_visual.gd输出HUMAN_STATUS_VISUAL_UI_OK。检查本地骑乘及远端实际绿色像素、七种叠加优先级、受击保留、站立外观更新、死亡状态刷新。actor_status.gd回归输出ACTOR_STATUS_UI_OK。两项约8秒，无引擎错误或退出泄漏提示。截图human-status-green.png、human-status-translucent.png、human-status-corpse.png。

本批不代表所有状态位玩法限制、人物阴影、特殊装备光效或原版逐像素对照已完成；仍由对应TODO追踪。未运行全场景测试。
