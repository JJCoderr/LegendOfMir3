# 技能窗口原包接入

## 原版依据

实时IDA：4282C0的0xD2/0xD3/0xD4分别调用44F730、44F4F0、44F670。640调用44F870。消息定义沿用CM_MAGICKEYCHANGE、SM_ADDMAGIC、SM_SENDMYMAGIC、SM_MAGIC_LVEXP；212在集中定义中按原版命名SM_DELMAGIC。

44F4F0接收参数三低字节为记录数量。每条记录先找正文中的/分隔符，再独立六位解码到74字节，不能将多个有尾部填充位的记录整体解码。次数到达计数后剩余正文忽略；零记录只清空列表。44F730新增消息直接解码单条74字节，不要求列表分隔符。

当前已解码模型依据原字段：+0 DWORD修炼，+4快捷键字符，+5等级字节，+6 WORD技能ID，+8名字，+31/+35/+39三个修炼门槛。全量快捷键字符1至9/A至C转槽号；新增只采用atoi值，A不建立快捷表。快捷表保存技能ID低字节。全量重建列表与删除技能都没有清空快捷表，保留此原版行为；跨角色离场才清除当前客户端会话数据。

640：recognition为技能ID，参数一低字节为等级，参数二与参数三按低/高WORD组合为DWORD修炼；44F870修改首条匹配记录。212从当前类别删除首条匹配记录并重新选择非空页。

44F8E0发生键冲突先清旧记录，调用47C0A0发取消，再对目标记录发设置；47C0A0生成CM_MAGICKEYCHANGE，recognition为完整技能ID，参数一为原字符值，参数二/三零，无正文。取消值0，F1..F9为1..9的ASCII，F10..F12为A..C。

## 实现与验证

新增SkillWire固定记录传输解析，接入游戏密钥头解码后的分发；新增/全量、修炼、删除接到现有C++窗口模型。截断、缺分隔符、非法六位编码和记录长度不符先拒绝，不能像原版不安全解码那样读越界或部分清列表。快捷键请求进入公共编码器并共享序号。离场清技能数据、快捷表、选择、滚动与弹出菜单。

Release构建通过；hud_checks --skill-wire覆盖独立编码、计数低字节、分隔、截断、空列表与无关类型。skill_wire.gd实际窗口覆盖完整分段原包、F1冲突解绑与F12编码顺序、等级低字节/全DWORD修炼、单条新增A键差异、坏列表保留旧状态、删除及空全量保留快捷表、重新全量和离场清理。截图skill-wire-progress/list.png在提交前展示。测试脚本开头为中文测试内容，未运行全场景。
