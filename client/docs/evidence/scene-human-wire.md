# 场景消息解码与 HP 队列合并

新增 protocol/receive_message.hpp：从现有 NPC 解码器抽出六位编码校验，按旧 receive_header.hpp 的 0x47D890、0x428308..0x428399 重建 16 字节编码头（12 字节解码头）。四字节连接密钥只参与已分析字段 XOR，不声称它提供完整性认证。NPC 仍使用同一六位解码器。

apply_scene_message 接收已经分帧的头和体，不含 TCP 包围符。当前限制编码体 1023 字节，检查 actor 范围、方向、消息形态和外观。移动/站立/受击/复活载荷的基础 22 字节与扩展 7 字节分别解码，不能把带独立 padding 的两段合并解码。外观按既有队列在出队时应用。

53/1312 直接走现有健康/登记入口；31 排队，积压至少两条时按 0x40D7F0 提前取出全部 31，更新 HP/maxHP、保留 MP且不产生伤害数字，其他消息顺序不变。1309 出队时按 header 参数更新 HP/maxHP，并按第三参数显示伤害，独立于 HP 差值；零伤害显示 miss 并不启动受击动画。来源 ID 若能解析为当前远端人物，则采用其武器决定碰撞音效。本地玩家网络 ID 映射尚未接入，不能把未知来源当成本地玩家。

定向验证：Release CMake；hud_checks --scene-wire 包括固定密钥消息头样本、非法填充位、截断、HP 合并次序；Godot --scene-wire 包括 NPC 共享解码回归、健康/登记、原始攻击、基础和扩展载荷、积压 HP 旁路、HP 减少 30 但消息伤害为 12 的数字校验、miss、非法包拒绝、尸体/复活及原始骑乘奔跑。截图 bichon-wire-hit.png、bichon-wire-mounted-run.png。未执行无关全场景测试。

范围限制：不是 TCP 接收器，未启动服务器联调；当前支持的队列 opcode 为 7/10/11/13/14/15/31/32/34/1306/1307/1308/1309/1316/1319/1321。带额外特效标记的攻击体暂拒绝，避免把未实现特效静默丢失；1309 命中特效 ID 尚未绘制。其他对象与名称/聊天等原始消息分发仍待补齐。
