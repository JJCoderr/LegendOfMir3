# 装备列表与耐久回包

## 原版依据

使用IDA技能实时查询mir3-map-review数据库的4282C0中621/642分支，复核4017A0的汇编、4AF358常量及49FE1C转换函数。当前业务实现独立于旧Godot工程。消息名称参考reference/LegendOfMir3_Src/LegendOfMir3_Client/Define.h中的SM_SENDUSEITEMS和SM_DURACHANGE，结构以1.45原版证据为准。

621正文为ASCII槽位/六位编码100字节记录/重复串。忽略头参数中的计数，最多处理12条。逐项直接覆盖指定槽位，不先清空全部装备；重复槽位最后一条生效，空正文保持原状态。原版atoi与未检查数组索引不安全，本实现仅接受完整十进制0至11槽位，完整解析和资源加载成功后提交，畸形记录不会部分覆盖。达到12条后不读取尾部，保留原循环上限。普通图标、纸娃娃Equip资源和偏移复用当前独立渲染路径。

642参数一是装备槽位，槽位越界或空槽时忽略。recognition低WORD写入物品记录66的当前耐久；参数二WORD写入68的最大耐久，参数三不参与。提示判断使用完整有符号recognition，而非存储后截断的WORD。

4017A0汇编为FILD整数、FIDIV单位、FADD常量0.5，然后跳转49FE1C截断转换。普通装备单位1000，StdMode54/55单位100。取整结果<=0时输出资源1470，用物品名称替换占位符，并经41C120使用调色板2前景及7背景。正值边界分别是499/500和49/50，不是999/1000或99/100。重复低耐久消息会重复提示，未增加去重规则。

新增equipment_wire.hpp解析装备列表与耐久；接入apply_game_message，保存完整物品记录并触发窗口重绘。未添加客户端自行修理或改变地图人物外观的行为，原分支只修改装备窗口数据。

- CMake Release构建mir3_client和hud_checks通过；既存坐标转换警告不变。
- hud_checks --equipment-wire验证槽位/记录分段、重复槽位、12条上限、异常包拒绝、耐久取整边界、完整recognition与截断存储的差异。
- equipment_wire.gd通过实际渲染验证指定槽位、空包保留、缺分隔符拒绝、部分覆盖、重复槽位、普通与特殊武器提示边界、空槽/无效槽位忽略；同时补测202装备删除、203重新插入首个空槽。
- inventory_wire.gd定向回归通过；未重跑无关窗口和登录全流程。
