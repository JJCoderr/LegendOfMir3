# 聊天输入分派与本地历史

## 原版证据

实时IDA数据库mir3-map-review，427400是输入框提交后的业务分派，43E5B0先处理编辑事件。界面按钮仍直接走47CA80，不经过输入分派。47CA80发送命名协议CM_SAY，recognition和三个参数均为0，正文为GBK六位编码，共享连接包序号。

- 空输入不处理。精确等于CMList1425（添加成员命令）时不发CM_SAY：有管理权打开1426姓名框，确认按4256B0→47CEE0发CM_GUILDADDMEMBER；无权显示1427。
- 精确`@chatsave`切换应用+72，精确`@snow`切换应用+40，两者随后仍发CM_SAY。
- `/`开头先调用4366D0，以调色板5/0显示原文。436F10抽取收件人并保留`/姓名 `前缀；437350保存不含开头斜线的`姓名 `条目。重复不移动位置，超过10项移除最旧项。单独`/`保留旧前缀。
- `#`开头调用4379D0，保存去掉首字符的短语，精确去重、最多10条、超限移除最旧项，然后直接返回，不发包。
- 精确匹配CMList1418/1428/1419时启动共用300ms动作延迟，再发CM_SAY。

4377F0/437F40以GBK文字和单字节`/`分隔保存至`Data/角色名(服务器名).slt`及`.mlt`。437680/437DD0按分隔符读取前10项。4876D0的525分支将选中角色名复制至4B9804，404D80选服路径将服务器名复制至4B97F0，确认文件名不是账号名。

协议命名来自reference/LegendOfMir3_Src/LegendOfMir3_Client/Define.h（CM_GUILDADDMEMBER=1038），使用现有集中message_ids定义，不在业务中写协议数值。

## 实现

ChatSubmission模型区分普通发送、私聊回显、本地短语、权限对话框及命令延迟；保存两项本地命令标志。HUD只向普通输入接入分派，send_chat_command仍直接发送一次，保留观察信号。

聊天控件先清空旧文本并离开焦点，再通知提交，避免新打开的姓名框被旧提交清空或失焦。新增行会加人提示及确认请求，复用原对话框资源和已有行会回包处理。

历史使用当前配置的用户Data目录（MIR3_ITEM_LAYOUT_DIRECTORY），不写原始资源目录；角色名或服务器名含非法路径字符时不访问文件。角色身份变化时加载对应历史，离场清空内存历史。损坏/异常过大的文件限制读取，不使用原版无界字符缓存。文件数量、GBK与分隔格式保持兼容。
