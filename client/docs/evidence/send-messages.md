# 客户端通用发送编码与1009退出请求

## 原版证据

2026-11-14复核0x47BE10、0x47D8B0与已有0x47C730发送证据。1009是无正文请求，recognition、第一/第二/第三WORD参数均为0。目标确认调用见 [退出流程](exit-flow.md)。

## 帧布局

发送头是12字节小端序：recognition DWORD位于0..3；opcode WORD位于4..5；三个WORD参数位于6..7、8..9、10..11。现有NPC接口将前两个WORD合并为32位instance，第三WORD为quantity，提取后保持其布局。

外层为 `#`、一位序号、六位编码头、单独六位编码正文、`!`。每6位加60形成传输字节；不足6位时向高位对齐补零。序号1至9循环，同一个发送器实例共享序号。正文取首个NUL之前的字节；编码头与正文分别处理，禁止把两段拼接后用跨段位余数编码。无正文请求总长19字节。

C++ `SendMessages`负责编码与序号；视图将Godot UTF-8正文按既有ANSI路径转换后调用。NPC请求和1009共享同一个实例，防止新增会话请求时重置或分裂序号。

## 会话接入

通用 `client_packet_ready(PackedByteArray)`包含完整待发送帧，当前覆盖既有NPC请求与1009。原 `npc_packet_ready`保留为兼容通知，NPC请求会同时触发两者，1009只触发通用通知。网络层应只订阅通用信号发送，不能同时把两个信号都写入socket，否则NPC请求重复发送。其余仍为语义信号的聊天/背包等请求尚未统一接入此发送器。

`handle_exit_confirmation(101)`生成1009；109仍结束SceneTree；其他编号忽略。八秒门禁已接入已解码本地状态接口，见 [退出限制](exit-guard.md)；本地战斗自动同步、缓存保存、真实服务器注销及角色列表/重新入场尚未完成；退出过渡与初始角色选择页见exit-transition.md。场景保留测试仅证明此请求没有错误走程序退出路径，该用例本身不验证过渡时间；完整过渡时序由--exit-transition单独验证。

## 验证

Release构建及原生 `--exit-request` 通过：精确头字段、无正文长度、NPC字段/正文NUL截断、共享序号和9到1回绕。Godot同名定向测试通过：取消无包、确认精确1009、随后NPC请求使用#2且兼容通知一致、再次退出使用#3、无关编号不发包；截图exit-request-confirmation.png与exit-request-scene-retained.png来自真实游戏视口。未运行无关全场景。
