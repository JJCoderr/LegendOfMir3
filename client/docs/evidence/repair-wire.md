# NPC 修理

4282C0 的 668 打开背包并切入模式 1，以识别号保存商人。441FD0 选择 1226/1227 按钮资源和 CmList 1702。4416F5 在该模式选中背包记录后请求 1024，识别号为商人，前两 WORD 为物品编号的低高半字，正文是物品 GBK 名。671 用识别号返回报价，零值取消确认。441834 和 441C79 在确认时以同一头和正文发送 1023。669 写入识别号携带的余额及前两 WORD 携带的当前和最大耐久，并显示 1456。670 显示 1457，恢复选择状态。

```text
668 → 打开背包修理模式
选择物品 → 1024 → 等待 671
有效报价 → 确认 → 1023 → 669 更新余额及耐久，或 670 显示失败
关闭背包 / NPC 关闭 / 离场 → 清空当前选择
```

客户端按服务器报价判断当前物品可否修理。特殊修理的 NPC 脚本入口和实服报价差异待核对。

Windows Release 与 `repair_wire.gd`、`inventory_wire.gd`、`npc_wire.gd` 已验收。报价按钮坐标 (198,401) 来自 43FE8D–43FEA9。比奇省报价和成功截图为 `npc-repair-quote.png`、`npc-repair-success.png`。修理用例退出时 Godot 报告两个 ObjectDB 实例。
