## 关键控制流伪代码

### 页面与场景生命周期

```text
启动 → 服务器组/账号配置 → 登录认证 → 选服/选择服务器会话
→ 查询角色/创建/删除 → 525给出游戏端点 → 游戏认证/密钥
→ 50本地身份及附加属性 → 首张地图/对象/物品状态
退出确认 → 原版动作时间限制 → 请求1009 → 过渡/清理 → 角色选择
连接错误、超时、拒绝和正常关闭分别走已确认的分支，不统一当成重连
```

详细证据见login-flow.md、character-selection.md、exit-guard.md、exit-transition.md；未识别的50附加16字节、系统132提示及实服时序继续保留A05/A06，不从伪代码推断为完成。

### 游戏消息分派（4282C0 → 42EC70）

```text
若输入为专用前缀：进入专用处理入口
否则：六位解码 → 按会话密钥还原recognition/opcode/三个WORD参数
按opcode分派：
    即时UI/列表/状态消息：解码正文，定位对应子对象并调用处理函数
    排队消息：保存头和正文，加入公共/人物消息链
    其他明确分支：保留原版条件/共享跳转，不按编号相近合并含义
公共队列消费：换图先于普通人物匹配；其他分支定位对象或全局处理
人物队列消费：按动作结束/积压/特殊HP消息规则更新模型
```

184个switch编号加12个额外显式相等编号形成当前196项登记。范围分支端点、共享label、登录分派和间接调用仍有补录项；记录它们比把未知消息归为“忽略”更可靠。

### 主界面与窗口（438000 → 436A30 / 43AB90）

```text
主界面绘制：头像/底栏/聊天/计量条/按钮 → 活跃窗口链 → 快捷提示等覆盖
活跃窗口链：逐节点读取窗口ID → 0..22跳转表 → 对应窗口draw
窗口切换：清当前操作状态 → 按ID检查可见性
    已打开：从顺序链移除、隐藏；特定窗口另外取消请求/归还编辑焦点
    未打开：加入顺序链、显示；特定窗口查询服务器或同时打开背包
窗口绘制后按命中ID绘制背包/状态/交易/商品等物品详情覆盖
```

输入次序和所有模态优先级仍需逐分支核对；不能把上述主干当成统一窗口管理器的完整规格。13/15/20/22等窗口存在各自特例。

### 输入（43D760 / 427400 / 425F00）

```text
键盘入口先处理当前窗口/编辑状态，再处理具体快捷键
聊天提交进入427400：本地命令/权限弹框/私聊回显/历史 → 按规则发CM_SAY
双击425F00转入主界面子对象处理；不同持有来源/窗口各走自己的分支
鼠标命中窗口、按下状态、释放位置与拖动捕获分别维护
```

已有详细聊天、快捷物品和选项证据直接复用；不得从“某按钮存在”推断场景点击可以穿透它。

### 新发现的寄售与信件系统

```text
寄售：服务器列表回复 → 窗口19分页/检索 → 选中商品 → 购买或撤销确认
登记：窗口20自动带出背包 → 放入物品 → 编辑价格 → 请求登记 → 成败恢复
信件：收件箱/发件箱 → 选择邮件 → 阅读/答复/删除
      编写 → 可选礼物/金币 → 发送 → 服务器结果/列表更新
```

这是从原版界面文字与入口得到的职责图，不是已恢复的报文或事务算法。1355–1358、1400与窗口19/21的关联有原版调用证据；具体购买/撤销/邮件附件回包顺序必须继续分析，不能照搬NPC商店或玩家交易。

## 清单完善与实现之间的边界

本批交付完整的开发范围总表、已发现窗口表、消息入口登记及未知项清单。并非完成客户端所有逆向工作：地图事件、完整怪物类型、所有技能、持续状态、扩展窗口18和未定名消息仍是明确待办。下一步按总表依赖集中分析某一模块，先形成足够实现的伪代码规格，再编码与功能测试。当前用户要求优先完成清单，天气3只保存已取得的证据，不继续实现。
