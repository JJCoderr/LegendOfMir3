# 选项状态消息 1401

## 原版证据

目标与哈希见 [选项窗口](options-panel.md)。2026-11-14 实时 IDA：消息分发 `0x4282C0`，case1401 调用点 `0x42D1DA..0x42D1E6`；状态应用函数 `0x464A00`。`0x428375` 写入解码头第一 WORD 参数，调用时从该位置取值；不能误用第二/第三参数。

消息沿用 16 字节六位编码头及四字节会话密钥。recognition 是 **无符号 32 位选项位图**，不是人物编号；第一参数为 unsigned short 攻击模式，其他参数在本函数中忽略。当前入口接收无正文的 1401，额外正文拒绝；尚未接 TCP 分帧与真实会话。

| 位掩码 | 确认字段 | 功能 |
|---|---|---|
| 0x40000000 | this[29] | 回生术 |
| 0x80000000 | this[30] | 天地合一 |
| 0x08000000 | this[31] | 交易 |
| 0x04000000 | this[32] | 私聊 |
| 0x02000000 | this[33] | 行会聊天 |
| 0x01000000 | this[34] | 加入行会 |
| 0x00800000 | this[35] | 所有人聊天 |

全部七项为 `0xCF800000`。IDA 显示的 `dword_800000` 在 `0x464C9A` 是立即数地址符号，实际执行 `and edi, 800000h`，没有间接读取。其他位不影响这些选项。

## 确认与预测

点击命令只预测帧，不写确认值。回包按位比较，**只有变化的确认位**才同时更新确认值及按钮帧；相同位保留现有预测，不强制重置。模式无条件写入 this[36]，因此重复位图仍可更新模式。原版未在此校验模式 0..4，原包入口保留完整 WORD；正常五种文字为 2116..2120，未知模式不做本地循环或替换。

`apply_options_state` 是测试/解码后整体注入接口，完整校验并覆盖全部显示；原始 1401 使用 `SystemOptions::receive` 的原版差量规则，两者不可混淆。

## 聊天底栏的原版副作用

这些变化以目标函数的顺序执行：私聊、行会聊天、所有人聊天。只有对应确认位变化才执行，重复包不再翻转。

- 私聊变化：依据旧拒绝变量 7678EC 设置底栏。旧值 1 时清遮罩、提示2637、变量置0；旧值0时帧1338、提示2638、变量置1。
- 行会变化：旧7678F0为1时清遮罩、提示2639、置0；旧0时帧1340、提示2640、置1。
- 所有人聊天变化：旧7678F4为0时清遮罩、提示2643；旧非0时帧1342、提示2644。随后翻转7678F4，并把 **7678F0 也写为翻转后的值**。该分支不更新行会底栏图标。

最后一条由 `0x464CDF..0x464D69` 的反汇编确认：`0x464D12` 写7678F0=1，`0x464D4D` 写7678F0=0。它可能是原版缺陷，但目标要求行为一致，因此保留；不能直接把三项拒绝变量都定义为允许位的反值。

例如初始确认与拒绝全0：收到全开位图后，拒绝变量为 `[1,1,1]`，底栏帧为 `[1338,1340,-1]`；随后全关得到 `[0,0,0]` 和 `[-1,-1,1342]`。再仅打开所有人聊天得到 `[0,1,1]`，底栏三项均无覆盖帧；行会变量变化但其图标未变，这是原版可观察的不一致。

## 验证与边界

CMake Release 构建通过。原生 `hud_checks --options-wire` 验证位图、重复确认、WORD 模式、无关位、聊天副作用与顺序；Godot `hud_smoke.gd -- --options-wire --screenshots` 验证实际编码头、最高位、点击预测、模式、非法额外正文的无副作用拒绝及底栏状态。截图 `options-wire-prediction.png`、`options-wire-confirmed.png` 为真实游戏视口。
