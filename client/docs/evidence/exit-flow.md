# 原版退出窗口与退出流程

## 目标与证据

2026-11-14 实时 IDA，目标映像哈希同 [选项窗口](options-panel.md)。以下区分已确认的原版事实、当前Godot行为和待追踪部分。

## 入口和确认

底栏释放处理0x43C130：按钮3调用0x421F60后打开109，提示CmList2636；按钮4同样检查后打开101，提示1065。现有Godot快捷键Alt+Q、Alt+X分别打开109/101，底栏左侧两个按钮同样分流。

原版通用确认框0x420A10处理Tab/Enter/Space，0x420BB0处理按钮释放，通过2030消息将对话框类别、按钮索引和输入文字送回主流程；0x4256B0按高字节类别分派。取消分支不执行退出动作。

- 类别101（反编译case e）：只有按钮索引0且再次通过0x421F60才执行。调用0x47BE10(1009)，再调用0x43EC60，最后主对象+0x43843C清0、+0x438438写2。
- 类别109（case m）：同样只在索引0且再次检查通过时执行。使用CmList1077构造相关文字并调用目标API，随后向主窗口发送消息2（WM_DESTROY）。API副作用尚未完整命名，不能据该文字推断额外UI。

0x47BE10使用0x47D8B0构造1009消息，recognition与三个参数全部为0；经0x47C730发送，没有正文。外层序号和六位编码规则与现有NPC请求共用目标发送函数，后续应统一会话发送器，不建立独立序号流。

## 八秒限制

0x421F60未正常生成完整伪代码，本结论直接来自0x421F60..0x421FE4反汇编：读取GetTickCount，并依序计算当前DWORD减主对象字段+0x36AE88、+0x36AE84、+0x36AE7C。三项全部严格大于0x1F40（8000）才正常放行；任一项小于等于8000则检查byte_7C1E98，等于0x13时放行，否则拒绝。比较指令为无符号JBE/JA，必须保留DWORD回绕语义与8000恰好仍受限的边界。

拒绝时调用聊天显示0x4366D0，文字CmList1407，调色板2为前景、3为背景。该检查既在打开确认框前，也在确认执行时出现：打开期间有新动作时，不可沿用旧的允许结果。

上述字段相对本地人物子对象分别为+0x628E0、+0x628DC、+0x628D4。0x415510将其初始化为0；已定位写入点0x415D09（0x415AD0）、0x419017（0x418D80）、0x417D2F（0x417C40）。后续已补证第一项在31/1309处理更新，第二项在技能分支更新，第三项在动作11的限制检查通过时更新；byte_7C1E98为本地人物动作字段，19是死亡。精确边界及当前接入范围见 [退出限制](exit-guard.md)。

## 当前实现与明确缺口

Godot `handle_exit_confirmation(109)`直接结束SceneTree；101现已通过共享发送器生成1009并触发client_packet_ready，见 [发送编码](send-messages.md)。八秒限制、拒绝提示和二次检查现已通过已解码状态接口接入；仍缺本地战斗状态自动同步、1009真实socket发送、退出状态2处理以及后续页面/网络清理。状态2的消费路径仍未定位，不能把它直接解释为某个确定超时或立即回到登录页。

窗口基线批次没有修改退出行为；后续发送批次只接入已查明的1009编码。接下来继续追踪三类时间字段、豁免字节、状态消费和0x43EC60，再实现完整链路并增加时间边界/确认期间状态变化/网络请求验证。

## 独立测试基线

`hud_smoke.gd -- --exit-dialog --screenshots`只验证当前窗口：Alt+Q打开109、Tab+Space取消、Alt+X打开101、Enter确认、底栏两入口分流、关闭后无重复通知。程序退出处理器在测试中断开，以检查信号而不结束测试进程；这不是1009发送或真实注销测试。

测试通过，生成实际800×600截图exit-dialog-program.png、exit-dialog-game.png；未跑无关场景。测试结束曾输出2个ObjectDB对象泄漏警告，保留为测试退出清理待查项，不把该运行描述为无告警。

补充分析：0x43EC60通过CreateFile/WriteFile保存三段缓存，长度143520、1200、18672字节，不是返回登录调用。具体缓存字段、路径和格式待进一步归档，不将本函数当作场景切换依据。
