# 主界面 IDA 复核

目标：宝藏版 Mir3.exe，原文件 SHA256 `FDCE0CF98757D64C18EB08F9346842E7028B93070872CD4C50A0BD116FD47195`。地址属于解包分析映像，不能直接作为原文件磁盘偏移。本次通过 IDA 数据库 `treasure-hud` 重新读取函数及指令；机器码、地址、反汇编保存于 `hud-layout-instructions.json`。

## 本次修正

`0x438000` 的调用顺序为：

1. `0x4384FC` 绘制展开聊天底色，位置 `(185,317)`、大小 `433×213`，颜色 RGB `(30,30,30)`，alpha 指令常量 `0x3F169697`。
2. `0x43854C` 绘制 GameInter[1160] 底栏。
3. `0x4385F6` 绘制 GameInter[1161/1162] 聊天框。
4. `0x438607/0x43860E` 绘制展开/普通聊天文字。
5. `0x438615` 调用 `0x4390E0`，绘制血球、计量条、等级、坐标和属性。
6. 按钮数组从后向前绘制。

原实现将展开底色置于底栏之后，且聊天文字绘制晚于血球和计量条。现已修正上述次序。聊天框坐标、底色矩形、文字行原点/宽度/行距/行数集中到 C++ `HudLayout`，经 GDExtension 提供给 Godot。

## 验证和边界

### 聊天滑块与按钮重绘顺序

`0x438641..0x438650` 与 `0x438740..0x43874F` 是两轮从后向前的按钮虚函数绘制；聊天滑块调用 `0x438729 -> 0x41FED0` 位于两轮之间。原实现仅绘制一轮按钮，并在聊天文字阶段提前画滑块。现恢复两轮及滑块所在阶段；地图绘制也按 `0x438000` 放在目标血量绘制之前。

`ChatScrollLayout` 统一帧 1207、x=619、普通/展开 y=507/342、行程 43/203、页行数 5/14，以及点击翻页判断使用的 12/2 偏移。输入与绘制取同一个 C++ 配置。`0x41FED0` 的比例经过 double 除法再存入 float；输出坐标从 float 比例与轨道行程计算后截断。已有滑块首尾、空列表、拖动和翻页测试仍适用。

证据：`0041FE80.txt`、`0041FED0.txt` 与 `chat-scroll-order-instructions.json`（92 条指令）。中间的 `0x438652..0x4386DE` 染色装饰分支后续已恢复，见 `hud-dye.md`；两轮按钮后的额外按钮分支仍未恢复，不能视为整个 HUD 调用链完成。

### 血球裁剪精度及共享矩形

`0x439270..0x43931A` 将 HP/MP 按 unsigned WORD 读取，比例先存入 float32，最大截到 1。`0x4393F7..0x439419`、`0x43966A..0x439709` 再读取该比例，计算 `height-height*ratio`；`0x49FE1C` 临时将 x87 舍入模式改为向零截断后 FISTP。原 GDScript 使用双精度比例，存在一行偏差。例如 1/3、96px 高时，原版 float32 路径裁去 63 行，原脚本裁去 64 行。

现在由 C++ `hud_orb_crop` 输出裁剪矩形，Godot 只加载原包纹理和绘制。战士低于 24 级时，`0x439454..0x439499` 的右半 GameInter[1165] 复用左半 [1163] 的完整裁剪矩形，不重新读取右半帧尺寸；其余分支分别计算 HP/MP。

`hud-orb-crop-instructions.json` 保存 203 条指令。测试涵盖 float32 一行差异、共享/独立尺寸、空血、满血以上、零上限、WORD 截断及非法参数。缺失/损坏帧返回空矩形是本项目的防护，不声称复现原版未初始化栈数据的行为。

### 血球与计量条提示的绘制阶段

再次读取 `0x435820`、`0x438000`、`0x4390E0` 后，修正之前将血球/计量条提示统一放在按钮后的实现：原版血球及其提示之后，先执行 GameInter[1167] 负重分支，再执行 GameInter[1166] 经验分支，各提示位于对应资源成功加载分支内；之后才绘制等级、坐标、属性并返回 `0x438000` 绘制按钮。现在即使计量条填充值为零，只要原帧存在，悬停仍能显示提示；帧不存在则不画该计量条提示。

`HudLayout::tooltip_at/tooltip_rect` 集中恢复命中及文字矩形计算，Godot 只提交绘制。构造函数的 RECT 字段为 `+0xC6C/+0xC7C/+0xC8C/+0xC9C`，分别为 `(33,475,69,563)`、`(73,475,109,563)`、`(148,490,160,586)`、`(161,490,173,586)`（此处是 LTRB）。PtInRect 的右/下边界排除；文字 SIZE 整数除以 2 后再构造矩形，保留奇数字宽截断。

证据：`00435820.txt`、`00438000.txt`、`004390E0.txt` 与 `hud-meter-order-instructions.json`。Release 构建和四项 CTest 通过；可视化冒烟增加四个实际鼠标悬停路径，完整流程通过。已查看 `build/bichon-hud-hover-165.png`，零负重提示可见。

对等级底图相关五个全局值进一步检查了 UPX0 整段原始地址字节引用，仍仅发现读取指令，没有直接写入。间接写入及生产路径尚待追查；全零模拟值仍未替换，不能据此断言原版运行时值也为零。

### 等级底图补全（再次通过 IDA 核对）

`0x43914A..0x43926B` 在血球和等级文字之前绘制 GameInter 底图，之前实现遗漏此调用。现由 C++ `HudLayout::level_emblem_position` 提供普通 `(385,456)`、展开 `(384,289)` 坐标，Godot 直接使用原包帧、不叠加 WIL 偏移。

`0x824750` 依次比较 `0x8F1CD4 / 0x8F1CD0 / 0x8F1CD8 / 0x8F1CDC`，匹配返回帧 `1201 / 1200 / 1203 / 1202`，未匹配则取 `0x8246A7` 经验值的低 16 位作为帧号。C++ 保留首个匹配优先及回退分支。证据为 `hud-level-emblem-instructions.json`，包含 77 条指令及机器码。

这些全局值的生产路径及语义尚未恢复，不能称其为职业映射。目前离线客户端显式使用全零模拟值，走首个匹配返回 1201；这不是对原版运行时取值的保证。新增分支、匹配优先级、截断与两种坐标验证随 CTest 通过，Release 构建通过。

CMake Release 构建通过；CTest 的 ui_state、messages、native_text、gameplay 四项通过。Godot 可视化冒烟检查完成并输出成功标记。已查看更新的 `build/bichon-chat-expanded.png`；运行时 GDI 默认及等级字体均解析为宋体，DPI=96，ACP=936。

这些证据支持已列出的坐标、参数和绘制顺序；不能据此宣称整个原版客户端逐像素一致。尚未完成原版运行时字体配置覆盖、目标 DC/DPI、DirectDraw 混色及同场景截图逐像素对照。聊天输入仍是 Godot LineEdit，虽然尺寸及字体参数已恢复，其光标、选区和字形渲染不是原生 Win32 EDIT 的完整复刻。其他尚未实现的 HUD 分支也不在本次保证范围内。
