# 离场时的物品会话清理

## 原版证据

实时IDA核对421E80→4217E0→4355C0/435180，以及4214A0。421E80在退出过渡结束后进入角色选择，4217E0清理游戏并关闭原连接；4355C0调用窗口清理虚函数，435180调用背包(+29440)、装备(+174924)和其它窗口的初始化虚函数，并清空持有记录及快捷物品缓存。原版不是只隐藏旧窗口。

另查43EC60确认其为Data目录下布局文件保存：写143520字节物品、1200字节占位表和18672字节快捷物品。此持久化功能不属于本批清理实现，仍单独待办，不能以清理替代保存/恢复。

## 当前缺陷与修复

clear_game_scene已有场景、技能和行会清理，但仅隐藏背包/装备/交易窗口。背包物品、持有状态、使用计时、装备待穿戴物品、交易双方物品、金币及商店数据会残留于同一HUD对象。

本次在既有离场边界重置InventoryGrid和EquipmentState，清除背包滚动行及指针，清空交易双方物品、金币余额/报价、待确认标志、返还位置、交易对象、滚动和确认状态。关闭NPC对话与商店，清除商品/报价列表及加载、选择、计时状态。不生成虚假的返还消息，不调用交易结算来清理。

此边界由返回登录、进入角色选择、进入游戏和服务器分组入口共用。资源贴图缓存继续由HUD持有；清理的是角色物品状态。旧确认因没有待确认事务而拒绝；非游戏页面的原包仍由现有页面检查拒绝。

## 定向验证

CMake Release构建mir3_client通过。item_session.gd实际窗口测试四类状态：

1. 背包使用待确认，返回账号登录。
2. 穿戴待确认，返回账号登录。
3. 交易双方物品/金币、商店列表，返回账号登录。
4. 普通鼠标持有物品，通过Alt+X确认及实际退出过渡进入角色选择。

四种情况下检查背包、装备、持有物品、待确认标志、金币、交易物品/伙伴/滚动相关状态及商店列表清空；迟到使用/穿戴/交易确认和物品新增原包不恢复旧数据，测试通过。第一次商店测试正文缺少原协议必需斜杠，修正测试数据后通过，未修改解析规则。

截图item-session-before-exit.png与item-session-selection.png位于client/build/screenshots，提交前已显示。没有重跑登录注册全流程，也未做真实服务器换角色重连联调；新的角色进入后由服务器重新发送权威物品状态仍需实服验收。
