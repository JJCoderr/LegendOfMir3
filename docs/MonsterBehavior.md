# 原版怪物行为与消息规格（C18）

生命结算已实现为 `MonsterVitals`：护甲后的正伤害若启用护盾，保留参考整数式 `(damage/100)*(level+2)*8`，护盾剩余时间减3且最低为1；护甲先降至0时不消费护盾时间。无人物装备的怪物受击仍抽取一次损耗随机数，破甲状态按参考ROUND使伤害乘1.2，再扣血并限制下界为0。直接负伤害则恢复生命，上限为最大生命；没有把已注释的魔法值代偿规则启用。

离线动物可用 `configure_reference_animal_combat` 一次性配置HP、DC、AC、命中、速度和等级。只有双方都具备显式配置的真实动物实体才执行近战扣血；未配置或合成可见目标仍保留动画夹具行为。实际生命即时更新，非人物受击触发被动选敌，受击表现排程550ms。零生命立即阻止AI和再次选敌，致死表现随受击投递启动；删除涉及对象及换图清理延迟记录。`animal-combat` 验证20→10→0、549/550ms、致死动作与旧可见快照不复活目标。攻击/生命属性是显式离线配置，护盾及破甲模型尚未同步场景状态，装备、联网权威结算、EXE对照仍待。

普通近战结算已建立 `MonsterMeleeAttack`（参考 ObjectEngine.cpp 1953–1974、1977–1989、2040–2160 的 CM_HIT 路径）。DC低字节加随机差值，反向区间将差值截到0；仅合格目标继续，目标命中点大于0才抽取速度随机数，攻击者命中点等于随机数时仍命中。正攻击力调用目标减伤，再抽取 `rand()%5+2-WeaponStrong`，正值交给装备回调；即使护甲已降到零，仍执行这一损耗阶段。最终正伤害先扣血，再排程550ms受击，非人物目标还追加即时受击。`armor_damage` 保留AC区间计算，反向AC直接使用低值；护盾由减伤回调负责，尚未移植。

原参考对“目标命中点大于0但速度为0”直接取模零，当前结果为明确的 `undefined_speed`，不冒充命中或闪避。装备指针有效性和是否装备武器由世界回调处理。模型测试验证随机调用次序、边界命中、完全护甲仍损耗、人物/非人物通知差异与反向区间；尚未接入场景实际生命、装备和原服伤害，EXE对照仍待。

参考状态同步：`ObjectEngine.h` 定义 `POISON_STONE=5`，`GetCharStatus` 用 `0x80000000 >> i` 编码状态数组，因此石化位为 `0x04000000`，与石像位1不同。`ReferenceMonsterStatus` 与判断函数集中于 Monster.cpp 接口；动物、蜂后和祖玛离线适配每轮从最新场景状态更新 petrified。动物移动、蜂后新增召唤、祖玛主动唤醒在石化时停止，清除后恢复，三个场景专项通过。蜂后已排程的投递仍先于Run，不增加石化丢弃规则。其他类型的状态映射仍待逐项接入。

`ObjectEngine.cpp:943–979` 的 GetNextDirection 在同格时返回DR_DOWN，两个距离修正分支的条件互相矛盾、实际不会触发。雷电僵尸专用模型已将同格方向从通用近战的-1修正为4并补测；该项已完成参考核对，EXE仍待。

受击选敌按参考 `ObjectMonster.cpp:854` 与 `ObjectEngine.cpp:99` 实现为 `MonsterRunState::struck`：存在合格攻击者即替换目标并刷新关注时间；等级小于50时对原攻击时间戳加 `150-min(130,level*4)`，不重设为当前时间。不合格或空攻击者仍执行时间戳调整，原目标保持不变。使用DWORD回绕语义，不能把时间戳加值直接解释为所有情况下固定延迟。肉质扣减代码仍为参考注释，不启用。

`notify_reference_animal_struck` 是显式离线通知入口，要求调用方给出攻击者、资格和等级；它不冒充原版网络包，也不结算伤害。动物场景专项验证不合格者不触发反击、合格者引发实际追踪与近战动作、攻击者离开可见集合后停止反击、死亡动物拒绝通知。参考等级0/10/33/49/50与时间回绕纳入模型测试。实际目标生命扣减、状态同步、服务器数据及EXE对照仍待。

动物离线场景现由 `spawn_reference_animal` 显式配置外观、方向和任务格，`advance_animal_monsters` 调用独立 AnimalMonster 与基类 Think/追踪/游走方法，移动进入现有场景动作与地图占位检查。专用动物实体排除在祖玛/远程外观自动分类之外。`animal-ai` 场景专项验证600ms严格边界、逐格到达、到达停留、邻近目标不触发主动搜敌、不可选敌对象仍阻挡、死亡停止、帧末删除、同ID重建和换图清理。外观21和600/1200ms是显式离线夹具值；未知肉量不生成产物。当前攻击只驱动动画，不扣服务器生命；状态映射、受击选敌、主人跟随场景及EXE对照仍待。

基类移动方法也统一于 `Monster.cpp`：`walk_to` 先检查禁锢，逃逸属性启用时还需目标格通过安全行走查询，然后交给世界移动函数更新坐标。`wander` 仅1/20进入行动，再以1/4概率转向（第二次随机值为1），其余沿当前方向走；只有转向分支读取第三次方向随机数。`go_to_target` 到达目的地时不做任何操作；否则只检查可见链表首项，合格且曼哈顿距离更近时选中并更新目的地，本轮返回。此处不检查隐藏状态。若未切换目标，记录寻路时间、先走直达方向，未移动则最多再尝试七次，每次以2/3概率顺时针转一格、1/3逆时针转一格。以实际坐标变化判定成功，不能仅相信移动回调返回值，也不能保证八次覆盖全部八方向。

模型测试覆盖首项重选、隐藏对象、八次阻挡、方向回绕、纵向移动停止重试、游走随机调用顺序和禁锢/安全格门控；动物任务调度已组合真实追踪与移动方法，验证逐步抵达并停留。世界地图碰撞/广播仍由适配层提供，尚未完成场景接入及EXE对照。

基类 `think` 与 `attack_target` 已作为 `MonsterRunState` 的实际方法落入 `Monster.cpp`。Think严格超过三秒才查同格重叠数和目标资格；重叠数至少2设置脱离状态，随后每次调用均可随机行走。参考只比较X变化，纵向移动不清除重叠状态。近战排除同格，八邻格内冷却未到仍返回已处理；冷却严格到期时更新攻击/关注时间与朝向，依次结算伤害、请求攻击动作、解除禁锢。射程外同地图更新目的地，不同地图清除目标和两个坐标。参考邻格检查先于地图检查，暂保留这一顺序。

模型集成测试已经把上述两个实际方法接到 AnimalMonster 的基类调度，验证冷却时不继续移动和到期攻击的顺序。碰撞移动、目标身份/属性、实际伤害和协议仍需世界接入；参考的X重复比较和邻格跨图行为仍待EXE确认，不视为最终原版结论。

`MonsterRunState::run` 保存参考基类调度（ObjectMonster.cpp 1217–1358）：非死亡、隐藏、幽灵、石像与石化状态才检查目标；超过30秒、目标死亡/幽灵或任一轴超过15格清除目标。禁锢到期后先调用Think，Think处理成功则直接进入继承调度；否则严格超过行走间隔才执行攻击与移动。攻击已处理时也直接进入继承调度。无目标可采用任务坐标；有主人时按其身后坐标修正目的地，任一轴距离不超过两格且身后有对象便停在自身格，距离主人任一轴超过20格时请求传送至主人地图。逃跑到期清除标志但本轮仍沿现有目的地移动。所有出口都调用继承调度。

`AnimalMonster` 直接使用这一基类，不添加主动选敌；Think、攻击、实际移动与继承调度目前仍是世界回调，必须由调用方更新同一状态。参考 CAnimalObject 的骨架、肉质和皮韧度字段没有初始化，当前显式保留未知值。CChickenObject 构造虽写肉质3000–4999、皮韧度50，但 Run 为空，ProcessMonster 的工厂创建被注释；不能把鸡参数用作鹿或所有动物的默认值。被注释的肉质下降代码不视为已启用规则。动物伤害反应、产物结算与世界调度仍待完成和EXE对照。

参考喷吐蜘蛛结算由 `SpitSpiderMonster::spit` 接收显式方向：DC低/高字节生成一次初始伤害，正伤害才请求普通攻击动作；随后按行扫描原5×5表的前4×4区域。北、西、西北保留两个格，其余方向只有一个格。每格只查询一个对象，排除自身、非合格目标和速度点为0的对象；随机值严格小于命中点才调用攻击者自身的减伤逻辑，并把结果继续用于后续对象。正结果立即扣血、排程300ms受击。未添加被注释掉的中毒效果。

蜘蛛 `AttackTarget` 尚未移植：参考 `TargetInSpitRange` 在一格内不写输出方向，远格读取 `[方向][X][Y]` 而结算扫描按 `[方向][Y][X]`；射程外又在不同地图时保留目标坐标、同地图时清空目标。这些问题需EXE证据决定，不能用普通追踪行为覆盖。当前测试只证明显式方向结算，不证明完整蜘蛛AI。

`MinorNumaMonster` 与 `OmaMonster` 独立保留专用选敌逻辑：有目标严格超过8秒、无目标严格超过1秒重搜，未找到替代者时保留旧目标，最后始终执行基类。MinorNuma只检查死亡；Oma额外检查幽灵，不自行加入石化门控。世界基类、数据库和外观映射仍待接入与核对。

召唤物参考生命周期也集中在 `Monster.cpp`。`WhiteSkeletonMonster` 首次运行先固定方向5、解除隐藏并请求钻出，再写 `now+2000` 的DWORD行走时间，随后执行基类。`ElfMonster` 首次钻出不改变方向，自身或主人有目标时克隆战斗形态；新战斗形态请求钻出并写 `now+800`，旧形态无论克隆是否成功都解除主人并移除，然后直接返回。`ElfWarriorMonster` 在双方均无目标时退回；仅克隆成功才请求钻回、换形，普通新形态静默出现并写 `now+800`，旧形态仍无条件解除主人、移除并继续基类。两个形态均在死亡严格超过两秒时请求幽灵化；首次出现先于死亡检查。

事件回调只能排队移除，不能同步释放正在运行的实例。克隆回调负责保存新旧世界对象标识，实际属性复制、主人链表替换、协议发送和基类调度仍未接入。时间写入忠实保留参考DWORD值，不等于已证明实际等待时长。这部分属于参考生命周期模型，尚未完成世界/EXE验收。

`RonMonster` 的参考专用分支以目标双轴距离小于六格触发攻击，但只查询自身周围一格对象并依次交给攻击回调。朝向使用缓存的目标方向，空查询仍请求普通攻击动作。`LightningZombieMonster` 在移动间隔严格到期且目标位于四格内时请求计算后退位置；两格内有三分之二概率提前交回基类，跳过本轮雷电且不消费攻击冷却。雷电独立判断五格范围和严格攻击间隔。两类均保留有目标八秒、无目标一秒的严格重搜条件，以及死亡、幽灵、石化门控。

以上实现集中在 `Monster.cpp`，目前验证专用 Run 模型。Ron 的地图查询和实际命中、雷电的穿透伤害与消息、后退后的基类移动、同格方向和外观映射尚待世界层及 EXE 对照，不能据模型通过宣称整只怪物完成。

`RockManMonster` / `SandMobMonster` 已在 `Monster.cpp` 保留专用参考分支。RockMan 隐藏时以八格方形范围检查合格对象，每次写 `walked_at=now+1000`；出现后有目标超过八秒、无目标超过一秒才重搜，重搜仍无目标则钻回。该原始 DWORD 时间写入不能直接当作“必定等待一秒”的证明，仍需核对基类时间减法。

SandMob 的阈值是整数 `MaxHP/20`：隐藏且 HP 严格高于阈值、八格内有敌人时只写出现时间，不直接显现。出现后正 HP 严格低于阈值且超过三秒才钻回，该路径仍检查选敌时机；目标双轴距离均大于15的钻回路径则立即返回，不继续选敌或调用基类。模型返回 `search`、`attack_target`、`skip_base` 请求，世界层尚需接入参考基类调度；死亡与幽灵禁用专用分支。两者仅完成参考模型测试，尚未完成世界/图形和EXE验收。

蜂后参考实现：`BeeQueenMonster` 的 `operate` 和 `run` 对应旧版 `CBeeQueen` 的两阶段处理。行动与攻击间隔均采用严格大于；有目标且随从数小于 15 时排程并通知世界播放攻击，500 ms 到期投递使用当前目标。上限只在排程时检查，投递不重新限额；创建失败消费消息且不占名额。死亡、幽灵或石化阻止新的排程和随从回收，但 `Operate` 中已经排程的消息不受该判断影响。对象真正销毁时队列随实例释放。世界调用方仍负责当前格生成幼蜂、通用目标失效检查与实际数据库原型；外观映射及 EXE 对照尚未完成。模型测试纳入统一入口 `monsters ai`。

世界适配补充：`spawn_reference_bee_queen` 显式接收母体、子体外观，母体采用固定位置，延迟队列创建真实场景对象并登记独立 `BeeMonster`。当前子体采用通用追踪夹具；目标、坐标及参考数据库索引会记录在生成结果中。`bee-queen-ai` 专项验证 499/500 ms 边界、同格生成、目标继承、追踪、母体死亡、显式删除和换图清理，图形截图已检查。73/74 只是该专项的外观夹具；正式数据库行、石化字段接入和 EXE 对照未完成。

实现统一位于 [Monster.cpp](../client/src/world/Monster.cpp)。新增怪物行为先以参考工程为基础，再逐项比对 EXE，差异以 EXE 为准。纯 C++ AI、动作/资源规则与 Godot 对象适配由同一文件实现，HUD 仅调用。`hud_monster_wire.cpp` 已合并到该文件，本文历史记录中的旧文件名只表示当时的位置。

食人花世界状态独立于客户端显示对象。`spawn_reference_monster` 隐藏出生，`advance_monster_ai` 按四格判定钻出，在目标双轴均大于四格时钻回；目标仅单轴远离或消失不直接钻回。近战按冷却重新选择视野列表首个合格敌人，固定位置攻击。钻回保留 AI、名称、状态和生命，显式删除或换图释放实体；死亡停止 AI。行动/攻击间隔 600/1200 ms 为夹具配置，伤害和原服配置待确认。

## 对象创建

`42E9A0` 允许尝试创建对象的完整消息集合为 **9、10、11、13、20、27、32、33、801、807、808**。需有可解码的外观和初始化成功；白名单不表示任意空包均能创建。

类型小于2走人物；类型4/5走另一虚表；其他非人物分支把类型规范为3，进入普通怪物。普通怪物先按头部坐标、动作0、方向0初始化，再重新投递原消息。34、800、806不在此创建白名单。13能触发创建，但不在普通怪物动作派发器的有效处理分支中。

## 动作时序

`40D8C0`在非站立且未标记死亡时不出队。出队前队长至少3设置追帧标记。`40E7F0`在首次计时换帧后把间隔减半并清该标记；行走由`40E9F0`的场景节拍推进，不能统一为固定毫秒动画。

动作4达到最后一帧后置死亡标志。死亡对象仍可消费消息；消费后若死亡标志仍在，恢复动作4末帧（或动作10），因此“处理器曾启动某动作”不保证最终画面保留该动作。起身清标志后才恢复活体流程。
