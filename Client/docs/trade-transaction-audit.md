# 原生交易完整流程迁移与验证

迁移基线8ff102a。原生交易窗口现已接入请求、放入/拆堆、取回、金币、完成/取消及失败恢复；使用CLIENT控件和现有资源，不依赖Godot运行时。以下先保留审查依据，再记录本批实测结果。

## 迁移前缺口

ExchangeWnd仅有显示、滚动、确认、金额提交、取回请求；pendingSlot只在Init赋值，没有放入交易栏路径。Offer缺少完整CItem/stackMode事务语义。GameProc未分派673..687交易结果消息。HUD交易按钮当前直接切换本地窗口，未选择正前方目标并请求服务端开窗。现有交易预览直接填充offers，不能证明背包放入/拆堆/回包流程。

读取Godot br_godot_test_261115：client/src/inventory/trade_grid.hpp；hud_view.cpp的trade_pointer、apply_trade_wire（9953）、send_trade_offer、apply_trade_offer_reply、apply_trade_gold_reply、apply_trade_complete、apply_trade_cancel、open_trade、request_trade（10282）；protocol/message_ids.inc。

## 实现范围

- HUD/对应按键按4281B0选择正前方一格的存活玩家发1025，收到673后初始化双方交易并打开背包；重复673只确保背包可见。关闭与完成/取消清理数量、金额弹框和拖动捕获。
- 每方最多12条记录，5列40行、38像素格。多格物品检查边界与重叠，优先指定格否则第一可放格；不能把200个锚点当成200件上限。
- 背包普通持有放入本方格，排除装备/快捷引用、使用或穿脱待确认；堆叠物品打开1307数量框，严格整数。匹配pending后发1026。
- 675部分放入使用wParam剩余量、recognition新交易instance，更新原始100字节记录并退回余量；全部放入清持有。676退回背包。容量不足时保持原状态，不能只回滚offers却已改变背包布局。成功同步快捷引用数量或删除引用。
- 677/678处理returnPending；成功时已有同名堆叠不再重复插入背包，金币名不插入；失败恢复交易格。声音按所处理物品播放。
- 682/683解码100字节原物品记录，按instance+name增删对方物品，提示1435/1436。673名称限制60字节，674提示1434。
- 684本方金币recognition，余额由wParam|wTag<<16恢复；686更新对方金币，两者播放106。687只清交易，不将对方展示物品复制到背包；权威物品/余额消息独立更新。
- 681取消先尝试恢复本方非堆叠与pending持有，再归还本方金币，保持容量失败不丢物。完成时按Godot的icon存在检查清理对应快捷引用。

## 实现补充

TradeWire.h集中请求、回包和提示编号。ExchangeWnd保留完整CItem及堆叠语义，临时交易格和InventoryWnd::RestoreItems共同保证取消/回退的批量原子恢复。交易待确认时背包鼠标按下/抬起、快捷使用、装备和场景丢弃入口保护同一持有物品。直接关闭窗口时先恢复已发出的pending物品；容量不足保留窗口与pending。

Interface的C键（忽略自动重复）及HUD交易按钮改发正前方角色请求；收到673才开窗。数量1307使用原生输入框，提交/取消和服务端关闭统一清理编辑控件。修复旧公会管理关闭按钮误切换交易窗口的问题，避免其干扰交易状态。未根据旧1025别名编造主动取消报文。
