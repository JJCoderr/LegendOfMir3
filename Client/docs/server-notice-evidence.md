## 原版依据

本批使用IDA读取Mir3-unpacked-analysis.exe.i64，会话78ac321b。Godot当前分支未找到消息658的公告窗口实现，因此以MIR3.EXE为准。

- 4282C0 case658先关闭通用提示，解码正文并以资源1250显示公告。
- 4812F0初始化按钮1251/1252，坐标131,429；481440居中窗口，已打开时忽略新正文；4818A0空正文不显示。
- 4815D0从窗口50,115绘制白字，文字测宽324px；整个正文宽度<=324直接绘制，否则逐字/双字节累积，到>=324换行，LF/ESC分行，最多21行，行高为字体高度+3。原版分隔符后保留旧buffer，因此连续分隔符可重复前行；已保持该行为（首次空行使用空串，避免原版未初始化读取）。
- 481550回车发送确认；481570按钮释放发送确认。47CA50确认消息为1018，全参数0。旧CLIENT在按下时提前发送且资源为0，已替换。

## 文字溢出的追查结果

- 当前真实资源入口为ImageHandler.cpp的第14项 `Data/GameInter.wil`；此前将来源记为Interface1c是记录错误。inspect_wil.py读取原WIX/WIL：1250为344×462，1251/1252为84×30。Interface1c的1250实际上是56×52，不能作为本窗口的证据。
- 再次追踪4815D0到48BCAF：后者GetDC、设置字体/前景、调用TextOutA、ReleaseDC，没有公告局部裁剪，也没有第二次缩放。48BF93直接GetTextExtentPoint32A测量；宽度324确为屏幕像素，不是字节数。
- 因而原版x+50加324px确实超出这套344px宽的背景；不能用任意缩窄或增加裁剪来冒充MIR3一致。本次保留原版算法。原版函数证据保存于out/server-notice-original-render.c。
- 补充样本mir3-baozang-monster-review.exe为VB启动器，MyMir3.dll不是该公告函数的替代证据，未据其猜测修补常量。当前资源版本与原版完整运行画面的最终对应关系仍未验证。
- 此次为同一公告功能的证据复核，没有修改运行代码，因此没有重复构建/运行检查。
