# 坐骑命令与换图输入延迟

依据Mir3/br_godot_test_261115的hud/map_input_delay.hpp和hud_view.cpp：坐骑命令/按钮300ms，进入场景1500ms；active期间拦截通用弹窗之后的左键按下、地图动作和技能。通用弹窗仍可操作，松开事件和移动事件并非全部屏蔽。

## 实现

- 复用CGameProcess两个原WORD计时字段，新增StartInputDelay/InputDelayed/AdvanceInputDelay方法；无数据成员或类布局变化。推进先比较剩余时间，避免大帧时长截断成WORD绕回；非正时长不推进。
- 输入框中的三个完整命令（CmList 1418/1428/1419）及坐骑面板有效命令按钮触发300ms，仍沿用原发送和按钮点击音效。字符串带额外内容不触发。
- 两处原2300ms的场景输入延迟对齐1500ms，人物过渡混合的独立2300ms不更改。
- GameProc左键/双击以及Interface左键入口消费延迟中的按下；通用提示和服务器公告优先处理。角色左右按键入口也检查延迟，防止持续按键绕过。新走路/跑步/攻击/挖取/转向及技能请求分别在对应本地入口拦截；已经接纳的动作队列及服务器动画仍继续推进。
- 不把延迟加入SpellPointerAvailable，因此地面名称、指针和目标显示不会仅因为延迟消失。技能快捷键的编辑绑定路径仍优先于实际施放拦截。

最初测试误用了不存在的SpellTiming.animated_at，已修为实际cast_at；最终七目标构建out/input-delay-final-build.log成功。新19+坐骑13+模态27+行会添加12+键盘34+音效15+聊天命令23+场景资源61+退出30=234项通过。十页新鲜截图和九份报告位于out/input-delay，两张新增图已查看，自启进程已停止。截图本身不证明计时边界，边界以实际处理函数及回环报告为据。
