# 模态提示优先级与原生编辑框遮挡

依据参考 hud_view.cpp 输入分派：group_dialog_input 先于 guild_editor_input 和其他面板输入。当前CLIENT此前在OnLButtonUp/OnMouseMove中有多个面板捕获分支早于模态判断，任务滚动、音量滑块、快捷栏/骑乘按钮会抢走提示点击；OnLButtonDown/OnKeyDown还把行会编辑器排在提示之前。

本批在鼠标按下/释放/移动入口优先处理提示，键盘也先处理提示。上一批仅依据输入分派，曾保留背景捕获。这一推断不完整：参考 open_group_dialog（8800附近）先调用 cancel_pointer_interactions（7338附近）。本次纠正为打开提示时清理临时按下/拖动/滚动状态，关闭后不恢复旧拖动；不注入会执行业务操作的鼠标释放事件。

实际截图额外发现原生行会EDIT窗口覆盖提示正文和按钮。ShowNotice立即隐藏行会EDIT并把焦点交回主窗；GuildEditor.Show按提示是否活动同步可见性，提示关闭后重新显示、恢复焦点，保留草稿文本。行会底板仍绘在提示下方。邮件/寄售已有单独编辑器遮挡逻辑，本批没有改写它们。

## 原生 EDIT 按键转发

发现 ChatEditProc 的游戏模态路径仍沿用聊天处理：Escape/功能键先移焦主窗，Tab也移焦；Enter固定执行YES，绕过当前按钮。参考 group_dialog_input 保留输入焦点，Tab切换选择，Enter使用group_selected，重复按键不执行。

游戏模态活动时，EDIT的Escape/功能键以及字符消息中的Tab/Enter统一交给Interface.OnKeyDown，系统快捷键不外泄；普通字符（包括空格）仍交给EDIT。游戏外聊天行为不改。新增通过实际SendMessage到EDIT的检查：Escape焦点、功能键焦点、Tab焦点、重复Enter、取消NPC输入清理、取消邮件金额不提交（17保持17而非输入23）。
