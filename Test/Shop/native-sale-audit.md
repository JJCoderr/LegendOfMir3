# 商店出售协议与参考服规则

参考对象：`G:/传奇3/Mud3/Eiserver.exe`，SHA-256：
`14DF4090E15BEA233FCC871574B1F050E7BCD3945DD38660D225B286B2FF2C06`。
以下为IDA静态分析与当前源码核对，本项目已接入普通物品单件出售；验证范围见下文。

## 原服证据

| 地址 | 行为 |
| --- | --- |
| 0x49F310 | 脚本头部以 `+` 开头的行解析为非负整数，加入商人偏移2688处的收购类型列表 |
| 0x4CD214 | 遍历该列表，只有物品标准记录的类型字节（偏移31）匹配才允许报价/出售 |
| 0x4CD81C | 校验类型，调用0x4D0BC4取得基础价，再调用0x4D0E90计算收购价；无效报价返回0 |
| 0x4D0E90 | `fild int32_base; fdiv float32(2.0); call ROUND`，不使用商人百分比，也不乘购买价的1.1 |
| 0x4CDAB4 | 单件成交再次校验物品类型、价钱、商人禁止收购标志和物品限制；转移金币成功才返回余额并调用0x4CD8C4回收物品 |
| 0x4CD950 | 堆叠成交使用数量乘已取整单价，检查剩余数量；成功回包含余额、剩余数与售出数 |
| 0x4CD8C4 | 物品耐久字段非零时，复制物品记录并加入该商人的库存分类；不能把出售一律实现为销毁物品 |
| 0x4CDA60 | 类型25/30且耐久低于4000的物品拒绝收购；不要把此规则泛化到普通药品 |

ROUND使用x87最近偶数取整（控制字证据见native-price-audit.md）。
基础价除以2的半整数在二进制中可精确表示，因此对非负32位价钱可用整数实现：
先取商 `base/2`，仅当余数为1且商为奇数时加1。
边界：基础价9/11/13/15分别得到4/6/6/8。不能复用购买单价或普通四舍五入。
原成交代码拒绝负价，但不以零价本身作为拒绝条件；当前客户端零报价会进入Unavailable状态，这两层行为需要区分。

## 当前客户端协议

| 用途 | 消息 | 字段 |
| --- | --- | --- |
| 打开出售模式 | SM_SENDUSERSELL (646) | nRecog为NPC身份 |
| 询价 | CM_MERCHANTQUERYSELLPRICE (1012) | nRecog为NPC；wParam/wTag合成物品实例ID；正文为名称 |
| 报价 | SM_SENDBUYPRICE (647) | nRecog为收购价，0表示界面不可出售 |
| 确认 | CM_USERSELLITEM (1013) | 同上；wSeries为数量，单件路径通常为0 |
| 单件成功/失败 | SM_USERSELLITEM_OK/FAIL (648/649) | 成功nRecog为最新金币 |
| 堆叠成功/失败 | MerchantService::StackSaleOk/Fail (1314/1315) | 成功nRecog为金币、wParam为剩余数量、wTag为售出数量 |

`CInventoryWnd::SelectServiceItem`、`QuoteService`、`ConfirmService`、`ReceiveService` 已存在。
成功响应由ReceiveService移除背包项或更新堆叠数，失败保持物品；成交结果不应再重复删除客户端同一项。
联调RPC应复用这些入口，并在state.get暴露实际service阶段、实例ID、报价。

## 接入核对与后续范围

- UserInfo.cpp已转发询价/出售的NPC、实例ID、数量和正文。
- ObjectPlayer.cpp已校验活NPC、地图/距离、当前出售上下文和真实背包实例；同名物品按实例识别。
- 已复用ResolveItemRequest/GetUseGenItem解析实例、IncGold/RemoveGenItem执行成交，沿用角色保存事务。成交时重新计算和校验，不使用客户端提供的价格。
- 商人已读取 `+类型` 收购配置。已配置商品的下一轮补货归回目标量；未配置商品收购后创建无补货目标的分类。装备及堆叠记录还需独立处理。

本阶段真实CSV覆盖：默认与非默认百分比下收购价相同、半整数取偶数、不收购类型、两个同名实例只移除指定项、余额上限失败不丢物品、重复出售拒绝、出售后回购与共享库存、保存重登。
现已实现普通物品单件报价/成交/回购，并以ShopSell系列CSV验证上述主要路径。数量堆叠出售、装备和附加属性/耐久折价仍未实现；不要将本阶段断言当作这些路径已兼容原服的证据。
