# 参考服商店价格核对

分析对象：`G:/传奇3/Mud3/Eiserver.exe`。
SHA-256：`14DF4090E15BEA233FCC871574B1F050E7BCD3945DD38660D225B286B2FF2C06`。
以下是 IDA 指令与调用关系的静态分析结果，尚不是原服务器动态交易验证。

## 已确认的行为

- `0x4985F0` 读取 `Merchant.txt`，在 `0x498846` 调用构造函数 `0x4E174C`。该构造函数在 `0x4E1787` 将商人偏移 `0x888` 的倍率初始化为 100。
- 脚本加载函数 `0x49F310` 在 `0x49F71F` 解析 `%` 后的整数，失败值为 -1；`0x49F727` 比较 55，只有大于等于 55 才在 `0x49F737` 更新倍率。低于下限或无效值保留原倍率，包括此前有效的倍率。
- 单价函数 `0x4D0E44` 按以下指令顺序计算：

```text
fild  base_price             ; signed 32-bit
fdiv  float32(100.0)         ; 0x4D0E80
fild  merchant.percent      ; merchant+0x888
fmulp
fld   extended80(1.1)       ; 0x4D0E84
fmulp
call  ROUND                 ; 0x402A44
```

`1.1` 的原始 80 位小端字节是 `cd cc cc cc cc cc cc 8c ff 3f`。
`ROUND` 使用 `fistp qword ptr [esp]` 转为整数；调用方只取 EAX。
默认 x87 控制字 `0x53A000` 为 `0x1332`，即扩展精度、最近值取整、平局取偶数。
不能直接用整数向下取整、C++ `round`，或默认双精度 `1.1` 替代而宣称完全兼容。
尤其需要验证中间浮点舍入对数学上半整数边界的影响。

- 普通商品列表 `0x4E0C38` 调用同一单价函数。
- 购买函数 `0x4CE1BC` 先调用 `0x4D0BC4` 取得物品基础价，再计算 `数量 * 单价函数结果`。余额不足或总价小于等于 0 时返回失败原因 3，不允许零价购买。
- `0x4D0BC4` 对批量普通物品返回标准价格；装备另有耐久和升级属性调整，尚未迁移验证。
