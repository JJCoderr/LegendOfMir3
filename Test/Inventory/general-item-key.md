# 普通物品实例键

`GeneralItemKey.h`统一GameSvr生成、保存、加载及物品操作使用的普通物品键。键仍为12个ASCII字节，数据库/DBSvr传输缓冲区仍为13字节（包含结尾NUL），客户端继续使用连接内独立实例ID。

## 格式

- 旧格式：`G` + 三位十进制标准索引 + 四位当前耐久 + 四位最大耐久。标准索引<=999且两个耐久<=9999时继续生成旧格式，例如`G00080008000`。
- 扩展格式：`G~` + 十个base32字符，字符表为`0123456789ABCDEFGHIJKLMNOPQRSTUV`。48位载荷从高到低依次为16位标准索引、16位当前耐久、16位最大耐久；50位字符容量的最高2位必须为0。
- 扩展格式是本工程内部存档约定，不是对原服存档格式的声明。可表示三个字段各0..65535，保持G前缀、12字节长度及SQL列宽；不改变客户端物品协议。

| 标准索引/当前耐久/最大耐久 | 编码 |
| --- | --- |
| 999 / 9999 / 9999 | `G99999999999` |
| 0 / 10000 / 10000 | `G~0000JH09OG` |
| 0 / 65000 / 65535 | `G~0003UUHVVV` |
| 1007 / 65535 / 65535 | `G~03TVVVVVVV` |
| 65535 / 65535 / 65535 | `G~7VVVVVVVVV` |

旧记录不用批量迁移。新GameSvr同时读取两种格式；写入扩展记录后，不能使用不支持该格式的旧GameSvr读取这些记录。DBSvr把键作为固定长度字符串保存，无需扩展列或修改客户端。

## 生成与保留属性

普通物品配置了非零FLD_DURAMAX时，新生成物品的当前和最大耐久均取该标准耐久。标准耐久为0时，继续沿用FLD_VAL1/FLD_VAL2作为旧实例初值，兼容现有数据。该初始化供商店购买、怪物掉落和AddNewItem共用。

回购先初始化商品再用回收记录覆盖，保留售出实例的当前/最大耐久，不能把受损物品重置为满耐久。存档、角色加载和按键读取标准索引/物品值均用同一编解码器；装备栏引用仍为完整12字节键。

## 验证

- `test_general_item_key`校验新旧黄金编码、每个16位字段的全部取值（共196608次往返）、缓冲区前后哨兵及非法字符/保留高位拒绝。构建：`cmake --build build-eiserver --config Release --target test_general_item_key`。
- `Shop/ShopSellHighDurability.csv`：加载65000/65535实例，出售、拒绝重复请求、购买三个10000/10000新商品及回收实例，分别检查新旧数据库键及保存重登。
- `Monsters/MonstersHighDurability.csv`：索引1007的物品掉落生成65535/65535，拾取、保存重登后使用；检查准确键值及最终消耗保存，覆盖操作时的扩展索引解析。
- `Inventory/InventoryHighDurability.csv`：索引1007、耐久65000/65535的蜡烛穿戴、装备引用保存重登、卸装、丢弃、行走拾取、新客户端实例ID和再次保存重登。槽位2沿用旧表FLD_LEFTHAND_ID列名。

普通物品耐久折价与商店实例购买已接入；尚未实现堆叠数量交易、同名普通装备多实例槽位语义，也未实测SQL Server及管理命令发物品。完整高标准索引65535由编解码单测覆盖，业务场景标准索引覆盖1007。
